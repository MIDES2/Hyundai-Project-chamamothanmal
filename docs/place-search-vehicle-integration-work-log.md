# 장소 검색과 차량 앱 연결

2026-11-11 요청: 가져온 조원 코드 중 연결 가능한 부분을 연결하고 서버 경유 외부 장소 검색(장소명·주소·위도·경도)을 추가한다. 최초 작업 트리는 깨끗했고 feature/backend-api는 원격보다10커밋 앞서 있다. 커밋·push하지 않는다.

## 작업 계획

- Kakao Local keyword/address 검색 프록시 /api/v2/places, 인증·입력·페이지·좌표 변환·외부 오류·키 비노출 처리. 실제 키 없을 때 가상 장소로 대체하지 않는다.
- 선택 주소 저장은 v2에 선택 필드로 추가하고 기존 H2 자료를 보존하는 컬럼 추가와 Supabase 002 SQL 제공.
- apps/web은 아직 README뿐이므로 웹 호출 예제를 제공하고 실제 웹 UI가 연결됐다고 하지 않는다.
- 기존 차량 테스트 화면은 보존하고 서버 연동용 화면을 추가해 :vehicle-state, Kotlin 서버 클라이언트, 실제 파일 수신·재생·세션·답장을 연결한다. debug MOCK은 명시적으로만 사용하고 SDK·오디오·UX·서버 권한을 따로 확인한다.
- 백엔드·Kotlin 회귀 및 새 검색 계약 시험, 차량 단위 테스트·Lint·APK 빌드. 가능하면 에뮬레이터 연결; 미실행은 기록한다.


## 완료한 변경

- Kakao keyword/address 프록시 GET /api/v2/places. 사용자 인증과 앱 탈퇴 상태 확인, 검색어·페이지 검증, 도로명/지번 주소 선택, x=경도/y=위도 매핑, 외부 오류/키 비노출, 최대1MiB 응답. 실제 키 미설정 시503을 반환하고 가상 장소로 대체하지 않는다.
- address 선택 필드를 등록·조회·클라이언트에 추가. 기존 주소 없는 클라이언트/중복 등록과 호환하고 H2 ADD COLUMN으로 기존 자료 보존. 원격은 Supabase 002_message_address.sql 수동 적용 필요.
- :app이 :vehicle-state·공통 Kotlin 클라이언트를 사용하도록 연결. 기존 MainActivity의 모의 로컬 재생은 보존하고 별도 ServerIntegrationActivity에 차량 연결·목록·공동 청취/이동·파일 수신·MediaPlayer·오디오/UX·재생 전/중 조건 확인·결과/답장 연결.
- 실제 재생 시작/완료 콜백에서만 보고. 순차 이벤트의 동일 ID/버전 재시도, 확인 안 된 보고가 있으면 새 재생 차단. 프로필/화면 이탈/목적지 변경·취소는 세션·재생을 정리한다. 사용자가 다시 누르기 전에는 자동 재개하지 않는다. 자동재생/백그라운드 서비스는 미구현.
- SDK/UX 불명확 시 차단. debug에서만 명시적으로 MOCK 기어·도어·위치·도착·UX를 사용하고 source=MOCK으로 보고한다. 실제 차량 상태 모듈의 SDK 구현은 변경하지 않았다.
- 토큰을 소스/APK에 넣지 않고 실행 시 입력한다. 공유 HTTP 클라이언트와 PC CLI 소스를 분리해 같은 통신 구현을 재사용한다. 차량 화면은 회전·프로세스 종료 시 재연결이 필요하다.
- prepare-vehicle-demo.ps1은 실제 Supabase 계정을 거부하고 local demo 계정만 사용한다. 합성440Hz 소리와 임시 연결 정보를 ignored build에 저장하며 콘솔에 인증값을 출력하지 않는다. search-places.ps1은 사용자 토큰을 로컬 설정에서 읽고 검색 결과를 반환한다.
- 웹 UI가 아직 없으므로 place-search.js→사용자 선택→upload-example.js 예제로 준비했다. 원본 .env/DB 보존. 커밋·push 없음.

## 검증 환경 주의

원본 경로는 JDK25의 File.canWrite/NIO 판정이 false지만 실제 파일 쓰기는 가능한 도구 환경이다. Gradle9의 프로젝트 검사 때문에 원본을 옮기지 않고 개인 설정/실제 음성/DB를 제외한 임시 소스 복사본에서 빌드했다. Gradle 테스트 결과 파일 rename도 환경 오류가 있어 결과 디렉터리만 작업 폴더로 지정한 init script를 사용했다. 프로젝트 코드의 테스트/검사를 비활성화하지 않았다. 최종 Kotlin/XML/Gradle 입력 해시가 원본과 일치함을 확인했다. 공식 Gradle9.6 배포 체크섬도 기존 Wrapper 값으로 검증했다. 원본 환경 설정·SDK 버전·Windows 보안 설정은 변경하지 않았다.

화면을 벗어나면 안전하게 이동을 종료하는 foreground 연동 프로토타입이다. 실제 로그인 UI·토큰 갱신·백그라운드/절전·OS 프로필 변경·다중 운전자 이양·카카오 지도 표시 UI는 별도 작업이다. 기존 로컬 raw 음성은 선택 사항으로 바꿔 파일 없이도 클린 빌드되게 했다.

저장소 기본 검사와 git diff --check 최종 통과. 빌드/개인 시험 정보는 Git 제외 확인. 도구가 실행한18084 시험 서버는 종료했고, 사용자의 기존 서버는 종료하지 않았다.
