# 최종 기획서 v3 백엔드 반영

## 계획과 범위

2026-11-09 사용자 요청. Spring Boot·Gradle 유지. /api/v2에 가족·차량·단기 일회용 연결 코드·이동 수신 동의·24시간 만료·재생 이벤트·버튼 답장·발신함·해제/삭제 추가. /api/v1은 로컬 회귀 시험에만 남기고 Supabase 인증 모드에서는 차단한다. 기존 .env와 H2의 v1 자료는 보존한다.

Supabase는 Auth 사용자 검증, PostgreSQL JDBC, 비공개 Storage 서버 프록시로 분리한다. 로컬 H2/시험 토큰을 기본값으로 유지하고 Supabase 프로필·마이그레이션·환경변수·설정 가이드를 제공한다. 클라이언트 직접 DB 쓰기는 허용하지 않으며 향후 RLS/RPC 구현을 거쳐 전환 가능하도록 규격을 기록한다.

실제 Supabase 프로젝트 정보가 없으므로 원격 인증/DB/Storage는 설정 코드와 로컬 HTTP 대역 시험까지 검증하고, 실제 연결 성공으로 표시하지 않는다. SDK·앱 UI는 조원 영역이며 수정하지 않는다. 커밋·push 금지.

## 검증 예정

기존 16 API 시험 유지, v2 가족/권한/코드 재사용/이동 동의/목적지/만료/삭제/답장/이벤트 중복 시험 추가. Kotlin·웹 예제를 v2로 전환하고 실제 HTTP 흐름 시험. Gradle check bootJar, 저장소 검사, diff 검사.

## 남은 실제 연동

Supabase 프로젝트/키/DB 연결/비공개 버킷 정보가 없어 원격 PostgreSQL SQL 적용·Auth·Storage·Auth 영구 삭제는 미실행. 기존 H2의 파일 재시작 쓰기는 사용자 터미널에서 확인 필요. 실제 로그인 UI·토큰 갱신, 브라우저 녹음 변환, Android 재생·SDK·오프라인 캐시 정리·프로필 변경·절전 복원은 조원 연결 필요. 오프라인 차량 캐시는 서버가 강제 삭제하지 못하므로 클라이언트가 새 재생을 보류하고 권한 재검증 후 정리해야 함.

서버/외부 파일은 단일 트랜잭션이 아니며 프로세스 강제 종료·업로드 응답 손실의 고아 파일은 후속 대조 작업 필요. 기록 정리는 서버 가동 중 기본60초마다 실행하며 실패 시 재시도. 현재 SQL은 클라이언트 직접 접근을 거부한다. 직접 Supabase 전환은 RLS/RPC/Storage 정책/작업 스케줄과 클라이언트 호출을 함께 이관해야 한다.

커밋·push를 하지 않았고 기존 사용자 서버를 종료하지 않았음. 도구가 별도로 실행한 시험 서버만 종료.
