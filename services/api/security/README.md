# 메시지 수신자 접근권한 검사

민석 담당. 서버 프레임워크와 독립된 Java 코드로, 지정된 수신자의 메시지 조회 및
음성 다운로드를 허용할지 판단한다. Java 11 이상에서 실행할 수 있다.

## 실행

저장소 루트의 PowerShell에서 JDK 경로를 지정한다.
아래는 현재 PC의 Android Studio JDK 경로 예시다. 다른 PC에서는 설치 위치로 바꾼다.

```powershell
.\services\api\security\run-tests.ps1 -JdkHome 'D:\Hundayi\jbr'
```

`JAVA_HOME` 또는 PATH의 JDK가 설정돼 있다면 `-JdkHome`을 생략할 수 있다.
컴파일 결과는 Git에서 제외된 이 폴더의 `build/` 아래에 생성한다.
테스트가 실패하면 스크립트가 오류를 발생시킨다.

## 서버에 연결할 때

1. 서버의 인증 처리에서 검증한 사용자 ID를 얻는다.
2. 메시지를 저장소에서 조회하고 저장된 수신자 ID를 얻는다.
3. `MessageAccessPolicy.evaluate(authenticatedUserId, storedRecipientId)`를 호출한다.
4. 결과에 따라 아래 계약 초안을 적용한다.

| 판단 | 서버 처리 |
| --- | --- |
| REQUIRE_AUTHENTICATION | 401 응답 |
| DENY | 404 응답. 존재하지 않는 메시지도 같은 처리 |
| ALLOW | 해당 수신자에게 메시지 또는 음성 반환 |

인증된 사용자 ID를 요청 body나 query의 임의 ID로 대신하지 않는다.
저장된 수신자 ID는 DB 조회 결과를 사용한다. 두 인자를 모두 클라이언트에게 받으면
임의 사용자 접근을 막을 수 없다. 메시지를 찾지 못하면 `storedRecipientId`에 null을 전달한다.

ID는 대소문자와 공백을 포함해 정확하게 비교한다. ID 발급·정규화 규칙이 필요하면
계정 시스템에서 먼저 합의한다. 송신자 열람, 관리자 권한, 재생 결과 갱신 권한은
아직 정의하지 않았으므로 이 정책을 임의로 확대 적용하지 않는다.
목록 API는 서버 쿼리에서도 수신자 범위를 제한하고 페이지네이션을 맞춰야 한다.

## 검증 범위

지정된 수신자, 다른 사용자, 누락·빈 인증, 누락된 메시지, 잘못된 수신자,
대소문자·접두사·공백·유니코드가 다른 ID에 대한 16개 검사를 제공한다.

현재는 권한 판단 함수와 테스트를 준비한 상태다. 실제 인증 검증, API 응답,
파일 경로 보호, 업로드 내용 검증 및 차량 앱 연동은 서버 연결 후 별도 검증한다.
