팀의 최종 문서에 맞춰 대상이 사람에서 차량·목적지로 변경됐습니다. 실제 앱은 /api/v2를 사용합니다. Spring Boot API를 유지하며 Supabase는 Auth·DB·비공개 음성 저장에 연결할 수 있습니다. 직접 Supabase로 개발 중이면 공개 DB 권한을 임의로 열지 말고 SUPABASE_SETUP.md의 전환 범위를 함께 검토합니다.

## 우선 실행

1. 기존 서버를 Ctrl+C 종료한 뒤 services/api에서 scripts/start-local.ps1 실행. 기존 .env·DB는 유지합니다.
2. 새 터미널의 같은 폴더에서 scripts/smoke-test.ps1 실행. 최종 v2 합성 데이터 흐름을 확인합니다.
3. Supabase 정보가 준비되면 설정 문서대로 SQL·비공개 버킷·로컬 환경변수를 직접 구성하고 명시적 프로필로 실행합니다. 원격 설정은 아직 적용하지 않았습니다.

## 실제 앱을 연결할 순서

1. 발신자가 가족을 만들고 초대 코드를 발급, 운전자가 자기 계정으로 가입합니다.
2. 관리자가 차량을 등록하고 연결 코드를 발급, 차량 앱에서 운전자 로그인 후 코드를 소모해 차량 토큰을 받습니다.
3. 웹에서 vehicleId·목적지·15초 이내 WAV를 등록합니다. recipientId/날짜 필드를 보내는 이전 예제는 사용하지 않습니다.
4. 차량 앱이 사용자 토큰+X-Vehicle-Token으로 후보 메시지 목록을 받습니다.
5. 실제 주차 중 운전자가 공동 청취·이번 이동 수신을 선택하면 source와 목적지·메시지 ID로 이동을 시작합니다.
6. 차량 앱이 받은 sessionId로 음성을 미리 받습니다. 운전 중 재생·답장을 요구하지 않습니다.
7. 도착·주차·문 닫힘·UX·오디오 조건과 온라인 권한/만료를 확인해 재생합니다. SDK 미확인 상태는 MOCK 시험과 구분하고 보류합니다.
8. 실제 재생 시작/완료 콜백으로 결과를 보고하고 주차 중 버튼 답장을 보냅니다. 발신자는 자기 메시지 상세에서 완료·답장을 확인합니다.
9. 목적지 변경·취소·프로필 변경 시 재생 중단·세션 종료. 문 열림/출발/오디오 상실은 즉시 중단. 사용자 중지 후 자동 재개 금지.

## 주소와 보안

같은 PC 웹은 http://127.0.0.1:8000, 기본 Android 에뮬레이터는 http://10.0.2.2:8000입니다. 다른 PC/실제 휴대폰은 서버 PC의 LAN 주소·API_HOST·방화벽·CORS를 별도로 설정해야 합니다. localhost가 다른 PC를 뜻하지 않습니다. debug HTTP 설정·INTERNET 권한은 차량 담당자 영역입니다. 운영은 HTTPS입니다.

실제 .env, DB 비밀번호, service_role, 사용자/차량 토큰과 연결 코드를 GitHub·로그에 넣지 않습니다. 차량 토큰은 재연결·프로필 변경 시 폐기합니다. Supabase 로그인·갱신 UI는 별도 연결이 필요합니다.

## 완료 기준

같은 messageId가 실제 웹에서 등록되고 실제 차량 앱의 동의한 sessionId에 연결돼 음성 수신·재생·답장·발신자 확인으로 이어져야 합니다. 다른 가족/기기, 동의 없음, 목적지 불일치, 만료/삭제/연결 해제에서 새 재생이 차단돼야 합니다. 오프라인 새 재생은 보류하고 캐시는 앱이 정리합니다. 현재 자동 API·HTTP 통신 성공을 실제 SDK·스피커 검증으로 표시하지 않습니다.
